# GEMA-CMS-004 — Production Readiness + Temporary Schema Cleanup + Staging Architecture

Status:

APPROVED

HIGH

# 1. Objective

Harden the GEMA CMS implementation for reliable staging and production operation:
1. Remove obsolete temporary CMS-002 media-routing schema (`homepage.signatureDishMedia`, `page-media.events`, `page-media.journal`) via a committed Payload migration.
2. Verify no dual content/media ownership remains across runtime domains.
3. Harden Preview/Draft workflow using Next.js Draft Mode requiring BOTH a valid `PREVIEW_SECRET` and authenticated Payload user (`editor` or `admin`) with strict path validation.
4. Implement targeted, draft-aware on-demand revalidation hooks (saving drafts does NOT invalidate public pages; publishing/unpublishing/deleting triggers targeted path revalidation; layout-tree/centralized navigation revalidation).
5. Prepare PostgreSQL deployment workflow with an isolated fresh database rehearsal script (`rehearse-migration-bootstrap.ts`) and environment-safe content bootstrap runner (`bootstrap-content.ts`) with `--initial`, `--verify`, `--force` modes.
6. Configure production-compatible media storage architecture using `@payloadcms/storage-s3` (atomic R2 configuration; local filesystem fallback when R2 env vars are omitted; S3 API endpoint for operations and `R2_PUBLIC_URL` for public serving; migration script `migrate-media-to-r2.ts`).
7. Implement `/api/health` checking DB reachability without exposing secrets (HTTP 200/503, `Cache-Control: no-store`).
8. Harden Admin security (server-enforced role access, no Editor self-promotion/admin creation, native admin grouping).
9. Verify end-to-end CMS editing, version restore, and operational rollback/backup plans.
10. Execute full regression, performance, build, and browser QA across all routes.

---

# 2. Reason

With CMS-001, CMS-002, and CMS-003 complete, Payload is the runtime source of truth for all content and media. CMS-004 ensures the application is production-ready, secure against unauthorized draft access, resilient to cache churn, clean of temporary migration schemas, and capable of running in both local development (filesystem media) and cloud staging/production (R2 media + PostgreSQL).

# 5. In-Scope Behavior

- Secure Draft Mode entry: requires BOTH `PREVIEW_SECRET` and authenticated user (`admin` or `editor`).
- Whitelisted redirect destinations: `/en`, `/id`, `/en/journal/*`, `/id/journal/*`, `/en/events/*`, `/id/events/*`.
- Draft Mode exit: `/api/exit-preview` disables draft mode and returns to public route.
- Provider draft support: `draftMode().isEnabled` enables `{ draft: true, overrideAccess: true }`.
- Targeted revalidation: draft save does NOT invalidate public pages; publish/unpublish/delete revalidates targeted routes.
- Navigation revalidation: layout-tree / centralized route revalidation.
- R2 S3 storage adapter: `@payloadcms/storage-s3`, atomic config checking `R2_BUCKET`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_PUBLIC_URL`.
- Local fallback: local filesystem when R2 is disabled/absent.
- Migration script: `migrate-media-to-r2.ts` for R2 asset migration.
- Safe content bootstrap: `--initial` (never overwrites live edits), `--verify` (read-only audit), `--force` (explicit overwrite).
- Rehearsal script: automated isolated fresh PostgreSQL database test.
- Health endpoint: `/api/health` returns `{ status: "ok" }` (200) or `{ status: "unavailable" }` (503) with `no-store` and no secrets.
- Admin grouping: `CONTENT`, `MEDIA`, `SITE`, `SYSTEM`.
- User RBAC: field-level and collection-level access control preventing self-promotion or unauthorized admin creation.

# 10. Risks

Functional:
- Revalidation might fail to purge cached pages if route paths are misconfigured.
Mitigation: Comprehensive empirical testing of all revalidation hooks.

Security:
- Unauthorized users accessing drafts or open redirect vulnerability in preview endpoint.
Mitigation: Require BOTH `PREVIEW_SECRET` and Payload authentication; strict path validation whitelist.

Data integrity:
- Bootstrap overwriting CMS editor changes.
Mitigation: `--initial` mode strictly checks for existing records and never mutates them.

Regression:
- Breaking image rendering if R2 is partially configured or local fallback fails.
Mitigation: Atomic R2 configuration check and explicit fallback to local filesystem.

# 11. Oracle Contract

## Normal Case
- Preview: Authenticated editor with valid `PREVIEW_SECRET` requests `/api/preview?secret=...&path=/en/journal/my-post` -> Draft Mode enabled -> redirects to `/en/journal/my-post` showing draft content.
- Exit Preview: Request `/api/exit-preview?path=/en/journal/my-post` -> Draft Mode disabled -> redirects to public route showing published content.
- Revalidation: Editing and saving a draft of Journal/Event does not invalidate public route cache; publishing invalidates `/en/journal`, `/en/journal/[slug]`, and `/en`.
- Bootstrap: `bootstrap-content.ts --initial` on existing database creates 0 duplicates and overwrites 0 records.

## Boundary Case
- Partial R2 config: Set `R2_BUCKET` without `R2_SECRET_ACCESS_KEY` -> process startup/build fails clearly with configuration error.
- Open Redirect: Request `/api/preview?secret=...&path=https://evil.com` -> HTTP 400/403 Bad Request, redirect denied.

## Error Case
- Anonymous user requests `/api/preview?secret=VALID_SECRET&path=/en/journal/my-post` -> HTTP 401/403 DENIED.
- Authenticated user without secret or with wrong secret requests `/api/preview` -> HTTP 401/403 DENIED.
- Database down -> `/api/health` returns HTTP 503 `{ "status": "unavailable" }` without database errors or secrets.

## Regression Case
- All public desktop and mobile routes render identically to CMS-003 baseline.
- Reservation modal, audio playback, chef animations function without error.
